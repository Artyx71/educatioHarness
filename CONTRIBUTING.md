# Участие в разработке educatioHarness

Спасибо за помощь. Проект разрабатывается по спецификациям: сначала фиксируем наблюдаемое поведение, затем реализуем и проверяем его. Главный принцип — не выдавать заглушку, макет или непроверенную сборку за работающую функцию.

## Перед изменением

1. Прочитайте [конституцию проекта](.specify/memory/constitution.md), соответствующую спецификацию в `specs/` и [архитектуру](docs/architecture.md).
2. Для нового поведения создайте или обновите `specs/<номер>-<название>/spec.md`. Опишите пользовательский сценарий, границы доверия, ошибки и проверяемые критерии приёмки. Для изменений в нескольких файлах добавьте `plan.md` и `tasks.md`.
3. Сверьте требования с существующими тестами и добавьте тесты на существенные переходы состояния и ошибки. Если требование нельзя проверить автоматически, укажите ручной сценарий и платформу.
4. При изменении контрактов Rust ↔ Node ↔ UI обновите все три стороны и не добавляйте вымышленные API SDK.

Проект использует AGPL-3.0. При переносе кода из LearnHarness сохраните обязательные уведомления и обновите [карту повторного использования](docs/upstream-reuse.md). Не копируйте сторонние материалы без проверки лицензии.

## Локальные проверки

На поддерживаемой Linux-машине с зависимостями Tauri 2:

```sh
npm ci
npm run typecheck
npm test
cargo test --manifest-path src-tauri/Cargo.toml
npm run runtime:bundle
npm run runtime:smoke
npm run desktop:build
```

`npm test` включает тесты frontend/runtime и sync-сервера. `runtime:smoke` проверяет, что поставляемые Node, Codex CLI и протокол runtime запускаются на текущем host. Он не выполняет реальный модельный запрос. Для проверки AI с действующим входом Codex есть `node scripts/smoke-learning.mjs`; она расходует лимит модели и не является обязательной для PR.

Для Windows/macOS сборку следует проверять на соответствующей ОС. Android/iOS не подтверждаются desktop-матрицей. Форматирование Rust пока не включено как обязательный CI gate: существующий код ещё не приведён к единому `rustfmt`, а массовое форматирование нужно отдельным PR. Перед добавлением такого gate сначала добейтесь чистого `cargo fmt --manifest-path src-tauri/Cargo.toml --check` на всём дереве.

## Pull request

- Делайте небольшие логические коммиты; не смешивайте переписывание стиля с функциональной правкой.
- Заполните шаблон PR: ссылка на спецификацию, критерии приёмки, выполненные команды и честно отмеченные непроверенные платформы.
- Не коммитьте ключи, токены, экспортированные `.ehb`, локальные базы и личные учебные данные.
- Для изменений импорта/синхронизации проверьте восстановление после ошибки и сохранность локальных учётных данных. Для AI-функций отличайте реальный ответ модели от тестового mock.
- Обновите README или целевую документацию, если изменились запуск, безопасность, ограничения или пользовательский сценарий.

CI сначала выполняет проверки на Linux, затем собирает пакеты на Linux, Windows и macOS. Пакеты доступны как временные GitHub Actions artifacts; это не подписанные релизы. Ограничение оплаты/лимита GitHub Actions сейчас не даёт заданиям стартовать, поэтому наличие workflow не доказывает успешную кроссплатформенную сборку. Публикацию и включение обязательных branch protection checks следует делать только после первого реально успешного прогона.
