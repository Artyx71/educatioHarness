# Свой сервер для защищённых архивов

Это минимальный одно-пользовательский сервер передачи `.ehb`. По умолчанию он хранит только зашифрованные архивы и не знает пароль архива, API-ключ или сессию ChatGPT. Регистрации, профилей и автоматического слияния изменений пока нет.

Требуется Node.js 22+ и абсолютный каталог данных. Пример запуска на серверной машине:

```sh
export EDUCATIO_SYNC_DATA_DIR=/srv/educatio-sync
export EDUCATIO_SYNC_TOKEN='случайная-секретная-строка-не-короче-32-символов'
npm run sync-server:start
```

Сгенерируйте токен генератором криптографически случайных байтов, например `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Не коммитьте и не записывайте токен в `.env` внутри репозитория. При запуске сервер слушает только `127.0.0.1:8787` (порт меняется через `EDUCATIO_SYNC_PORT`). Для доступа с другого устройства нужен доверенный HTTPS reverse proxy или приватный туннель с HTTPS. Прямой HTTP в локальную сеть не открывается; приложение не принимает удалённый HTTP-адрес.

В приложении откройте «Настройки → Свой сервер», введите базовый HTTPS-адрес и токен. Проверка делает настоящий HEAD-запрос. На компьютере токен сохраняется в системном хранилище секретов, адрес — в локальных настройках. Мобильная ветка пока держит токен только в памяти: после перезапуска его нужно ввести снова. Затем на компьютере:

1. Создайте защищённый `.ehb` в «Перенос данных».
2. В «Свой сервер» укажите пароль этого архива и выберите файл для отправки. Пароль проверяется локально и не отправляется серверу.
3. На другом компьютере подключите тот же сервер и нажмите «Скачать и развернуть данные», введя пароль. Приложение проверит архив, сохранит резервную копию текущей базы и только после успешного импорта запомнит версию сервера. Кнопка «Скачать .ehb» сохраняет отдельную копию файла, но не принимает его версию для последующей отправки.

Сервер требует токен для GET/HEAD/PUT `/v1/archive`. `GET /health` не раскрывает данные и не требует токена. Если на сервере уже есть архив, новое устройство сначала должно его **импортировать напрямую с сервера**: клиент запоминает ETag только после успешного импорта и запрещает отправку при расхождении. Перед заменой показывается подтверждение. Сервер отвечает `412`, если архив изменился между проверкой и отправкой. Первое размещение требует `If-None-Match: *`. Скачивание файла само по себе не объединяет занятия и не даёт права заменить серверную версию. Ручной импорт любого файла сбрасывает прежний ETag; после него для отправки понадобится прямой импорт с сервера. Импорт не сливает изменения двух устройств: текущая база заменяется, но её копия остаётся в каталоге данных. Профиль, занятия и граф переносятся; провайдер, модель, соединение с сервером, локальные пути навыков и идентификаторы сессий ИИ остаются настройками устройства. Предыдущие объекты остаются на диске по SHA-256 и могут быть восстановлены вручную администратором, но пользовательского интерфейса версий пока нет. Ограничение — 100 МБ исходной базы плюс 52 байта заголовка и тега. Защита от одновременных PUT действует внутри одного процесса; запускайте только один экземпляр на каталог. Резервное копирование каталога сервера остаётся обязанностью администратора.

Необязательный серверный AI-шлюз принимает только `POST /v1/agent` с тем же Bearer-токеном и ограниченным набором учебных операций. По умолчанию включите его переменной `EDUCATIO_AGENT_API_KEY` на серверной машине: он вызовет OpenAI Responses API. Ключ храните в секретах сервиса/окружения, не в репозитории. На телефоне подключение к серверу выполняет реальный короткий запрос `validate` к выбранной модели: архивный сервер без AI-шлюза отклоняется с понятной ошибкой и не отображается как готовый ИИ. На компьютере архивное подключение остаётся доступным без AI-шлюза, если модель выбирается отдельно.

Альтернатива для **личного доверенного сервера** — официальный Codex SDK с отдельной сессией ChatGPT того пользователя ОС, под которым запущен сервер:

```sh
# На сервере: создайте отдельный пустой каталог вне EDUCATIO_SYNC_DATA_DIR
export EDUCATIO_AGENT_PROVIDER=codex
export EDUCATIO_AGENT_WORKSPACE=/var/lib/educatio-agent-workspace
codex login --device-auth
codex login status
npm run sync-server:start
```

Создайте каталог заранее с правами для сервисного пользователя; выполняйте вход под **тем же** пользователем. Для сервера с браузером можно использовать обычный `codex login`. [Официальная документация Codex](https://learn.chatgpt.com/docs/auth) описывает оба способа. Сервер не читает и не пересылает токены Codex вручную: SDK использует штатное состояние CLI. Это не вход мобильного пользователя в его собственный ChatGPT — запросы расходуют доступ и лимиты серверной учётной записи. Клиент не может выбирать серверный провайдер, инструменты, путь к навыку или команду shell; режим задаёт администратор. Для Codex требуется отдельный рабочий каталог вне папки архивов, вызов идёт с `read-only`, без сетевых инструментов и без запроса повышенных прав. Но Codex-процесс может читать другие файлы, доступные сервисному пользователю ОС: запускайте его под отдельным пользователем без доступа к посторонним секретам и не выдавайте общий токен сервера чужим людям.

**Это не сквозное шифрование учебных запросов:** сервер и провайдер модели получают текст задания и ответа пользователя. Не включайте шлюз на недоверенном сервере. Runtime запускается как дочерний процесс с ограниченными входными данными и возвращает валидированный JSON. Desktop- и Android-клиент могут выбрать «Свой сервер» как провайдера ИИ после подключения в настройках. На Android API 36 emulator через этот маршрут пройден полный учебный сценарий с реальным Codex. Без настроенного режима AI endpoint отвечает `503`, не имитируя ответ модели. Доступность выбранной модели зависит от учётной записи на сервере; на проверенной Codex-сессии `gpt-6.1-sol` ответил на запрос проверки.

Отключение в настройках удаляет локальный токен и адрес, но не удаляет удалённый архив. Чтобы отозвать доступ, смените `EDUCATIO_SYNC_TOKEN` на сервере и заново подключите доверенные устройства. Для нескольких пользователей нужен отдельный серверный протокол с аккаунтами; этот MVP не выдаёт один токен нескольким людям.

В мобильном интерфейсе предусмотрен перенос без файлового диалога: «Зашифровать и отправить данные» создаёт архив прямо из локальной SQLite-базы; «Скачать и развернуть данные» проверяет пароль и схему, создаёт локальную резервную копию и заменяет текущую базу после подтверждения. Эти команды не выполняют автоматическое слияние и не отменяют защиту ETag. Синтетический архив, созданный на Linux-хосте штатным Rust-кодом, импортирован в Android-эмулятор с сохранением учебных записей и происхождения графа. Linux desktop GUI-импорт и экспорт `.ehb` проверены отдельно на синтетических данных; перенос на физический телефон не проверен. После перезапуска телефона токен нужно ввести снова, но сохранённые учебные данные можно открыть без ИИ.

Проверка сервера: `npm run sync-server:test`.
