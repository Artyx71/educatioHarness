# Свой сервер для защищённых архивов

Это минимальный одно-пользовательский сервер передачи `.ehb`. По умолчанию он хранит только зашифрованные архивы и не знает пароль архива, API-ключ или сессию ChatGPT. Регистрации, профилей и автоматического слияния изменений пока нет.

Требуется Node.js 22+ и абсолютный каталог данных. Пример запуска на серверной машине:

```sh
export EDUCATIO_SYNC_DATA_DIR=/srv/educatio-sync
export EDUCATIO_SYNC_TOKEN='случайная-секретная-строка-не-короче-32-символов'
npm run sync-server:start
```

Сгенерируйте токен генератором криптографически случайных байтов, например `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Не коммитьте и не записывайте токен в `.env` внутри репозитория. При запуске сервер слушает только `127.0.0.1:8787` (порт меняется через `EDUCATIO_SYNC_PORT`). Для доступа с другого устройства нужен доверенный HTTPS reverse proxy или приватный туннель с HTTPS. Прямой HTTP в локальную сеть не открывается; приложение не принимает удалённый HTTP-адрес.

В приложении откройте «Настройки → Свой сервер», введите базовый HTTPS-адрес и токен. Проверка делает настоящий HEAD-запрос. На компьютере токен сохраняется в системном хранилище секретов, адрес — в локальных настройках. Мобильная ветка пока держит токен только в памяти: после перезапуска его нужно ввести снова. Затем на компьютере:

1. Создайте защищённый `.ehb` в «Перенос данных».
2. В «Свой сервер» укажите пароль этого архива и выберите файл для отправки. Пароль проверяется локально и не отправляется серверу.
3. На другом компьютере подключите тот же сервер и скачайте архив. Импортируйте его через «Перенос данных», введя пароль.

Сервер требует токен для GET/HEAD/PUT `/v1/archive`. `GET /health` не раскрывает данные и не требует токена. Если на сервере уже есть архив, новое устройство сначала должно его скачать: клиент запоминает ETag последней известной версии и запрещает отправку при расхождении. Перед заменой показывается подтверждение. Сервер отвечает `412`, если архив изменился между проверкой и отправкой. Первое размещение требует `If-None-Match: *`. Скачивание само по себе не объединяет занятия: проверьте и импортируйте полученные данные перед следующей отправкой. Предыдущие объекты остаются на диске по SHA-256 и могут быть восстановлены вручную администратором, но пользовательского интерфейса версий пока нет. Ограничение — 100 МБ исходной базы плюс 52 байта заголовка и тега. Защита от одновременных PUT действует внутри одного процесса; запускайте только один экземпляр на каталог. Резервное копирование каталога сервера остаётся обязанностью администратора.

Необязательный серверный AI-шлюз включается переменной `EDUCATIO_AGENT_API_KEY` на серверной машине. Он принимает только `POST /v1/agent` с тем же Bearer-токеном и ограниченным набором учебных операций, вызывает OpenAI Responses API через тот же агентный runtime и возвращает валидированный JSON. **Это не сквозное шифрование учебных запросов:** сервер и OpenAI получают текст задания и ответа пользователя. Не включайте шлюз на недоверенном сервере. Ключ храните в секретах сервиса/окружения, не в репозитории; ChatGPT-сессия Codex для этого endpoint не подходит. Runtime запускается как дочерний процесс с ограниченными входными данными; запрос не может выбрать инструмент, путь к навыку или команду shell. Desktop-клиент может выбрать «Свой сервер» как провайдера ИИ после подключения в настройках; мобильный клиент ещё не собран. При отсутствии ключа endpoint отвечает `503`, не имитируя ответ модели.

Отключение в настройках удаляет локальный токен и адрес, но не удаляет удалённый архив. Чтобы отозвать доступ, смените `EDUCATIO_SYNC_TOKEN` на сервере и заново подключите доверенные устройства. Для нескольких пользователей нужен отдельный серверный протокол с аккаунтами; этот MVP не выдаёт один токен нескольким людям.

В мобильном интерфейсе предусмотрен перенос без файлового диалога: «Зашифровать и отправить данные» создаёт архив прямо из локальной SQLite-базы; «Скачать и развернуть данные» проверяет пароль и схему, создаёт локальную резервную копию и заменяет текущую базу после подтверждения. Эти команды не выполняют автоматическое слияние и не отменяют защиту ETag. Код мобильной ветки ещё не проверен на устройстве или в APK.

Проверка сервера: `npm run sync-server:test`.
