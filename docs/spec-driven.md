# Разработка по спецификациям

В репозитории установлен каркас [GitHub Spec Kit](https://github.com/github/spec-kit) с интеграцией Codex. `.specify/` содержит шаблоны и конституцию, `.agents/skills/speckit-*` — инструкции для Codex, `specs/` — проверяемые требования к конкретным изменениям. Это не значит, что весь прежний код задним числом подтверждён спецификациями: новая практика начинается с текущих изменений.

Разработчику нужны Python 3.11+ и `uv`. Версия CLI закреплена на официальном релизе v1.4.0:

```sh
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git@v1.4.0
specify version
```

Инициализация проекта уже выполнена; повторять `specify init --here --force` при обычной работе не нужно. Для нового сценария сначала уточните наблюдаемое поведение в `specs/<номер>-<название>/spec.md`, затем подготовьте план и список задач. В Codex доступны `$speckit-specify`, `$speckit-plan`, `$speckit-tasks`, `$speckit-implement` и `$speckit-converge`. Шаги вызываются в чате агента, а не как команды терминала. Проверяйте дифф и результаты каждого шага; сгенерированные пункты не являются доказательством прохождения тестов.

Текущая активная спецификация — [мобильное обучение и защищённый перенос](../specs/001-mobile-learning/spec.md). Конкретные команды и правила PR — в [CONTRIBUTING.md](../CONTRIBUTING.md). CI не отмечается успешным, пока GitHub фактически не запустил задания; сейчас этому мешает ограничение Billing & plans аккаунта.
