# Разработка

Окружение: Node.js 22+, npm, Rust stable, Tauri 2, GTK 3, WebKitGTK 4.1, libsoup 3, Secret Service. На Arch Linux проверены Node 26.7.0, Rust 1.98.0, WebKitGTK 2.52.6.

```sh
npm install
npm run tauri dev
npm run build
cargo test --manifest-path src-tauri/Cargo.toml
npm run desktop:build
```

Перед `tauri dev` автоматически запускается `runtime:bundle`: esbuild собирает runtime и копирует исполняемый Node и официальный Codex CLI для текущего host triple в `src-tauri/binaries/`. Tauri помещает оба бинарника и модуль в ресурсы. На другой платформе сборку нужно выполнять на её архитектуре; копирование системного Node подходит только при совместимой версии и архитектуре. На Windows у sidecar должно быть расширение `.exe`. Платформенные настройки Tauri задают NSIS для Windows и app/dmg для macOS; Linux дополнительно собирает RPM командой `npm run desktop:build:rpm`. GitHub Actions настроен для трёх host-ОС, но успешные прогоны Windows/macOS ещё не получены. На 11 ноября 2026 года задания не стартуют из-за ограничения оплаты/лимита GitHub Actions в аккаунте; это не результат выполнения сборки. Прямой запуск `node agent-runtime/dist/main.js` используется при разработке. В Hyprland приложение включает XWayland и программную отрисовку из-за ошибки WebKitGTK/GBM на проверенной системе.

В UI на первом запуске показано подключение. Для ChatGPT используется официальный комплектный Codex CLI (`codex login status`, `codex login`, `codex logout`), который разделяет штатное состояние входа с установленным CLI; для API-ключа — Secret Service, macOS Keychain или Windows Credential Manager. Приложение не читает файлы токенов Codex и не использует ChatGPT-сессию для прямого Responses API. Новый API-ключ проверяется реальным запросом через отдельный runtime до записи в системное хранилище; отказ модели или ошибка авторизации оставляют прежний ключ неизменным. Отдельная кнопка проверки подключения также делает реальный запрос модели.

Тесты без оплачиваемых запросов проверяют миграции, контракты и восстановление частично сохранённой диагностики. Реальный сквозной прогон (требует входа `codex login` и расходует лимит модели):

```sh
npm run runtime:bundle
node scripts/smoke-learning.mjs
```

На проверенной Codex-сессии 11 ноября 2026 года прошли все операции: диагностика, оценка, план, урок, упражнение, проверка ответа, извлечение и аудит графа. В нативном Tauri-окне отдельно пройден сценарий «цель про C → четыре диагностических вопроса → семь тем плана → интерактивный урок → карточка и оценка → два утверждения графа». После перезапуска приложения занятие и ответ в практике остались доступны; источник утверждения раскрывается в графе. Эта проверка использовала действующую ChatGPT-сессию, но не подтверждает доступность другого аккаунта и не заменяет интерактивный прогон на Windows/macOS.

Актуальный Linux release повторно собран командой `npm run desktop:build`: получены `.deb` и AppImage. Из созданного `.deb` отдельно извлечены поставляемые Node, Codex CLI и `agent-runtime/main.mjs`; они сообщили версии Node 26.7.0 и Codex CLI 0.167.0, официальный `codex login status` увидел действующий вход, а упакованный runtime выполнил реальный запрос `validate` к `gpt-6.1-sol` и вернул `connected: true`. Это проверка AI-цепочки именно Linux-пакета на текущей машине, но не интерактивный прогон установленного `.deb`, AppImage или другого дистрибутива.

Пути `vendor/<triple>/bin/codex` дополнительно сверены с официальными пакетами Codex CLI 0.167.0 для Windows x64 и macOS x64/arm64 через `npm pack --dry-run`; сборки на этих ОС это не заменяет. На текущей ChatGPT-сессии переключение на `gpt-6.1-terra` и `gpt-6-luna` проверено реальными запросами `validate` через упакованный Codex runtime. Доступность моделей у других аккаунтов может отличаться.

Итоговое повторение отдельно проверено в нативном окне с временной базой: две изученные темы дали два разных вопроса через реальный Codex; после перезапуска открылся первый неотвеченный вопрос, ответы и оценки сохранились, а завершение перевело workflow в `completed`. Эта проверка выявила, что прежняя валидация Rust отклоняла пустое необязательное поле «Ход мысли» уже после успешной оценки модели. Теперь пустое поле сохраняется как наблюдаемый факт; если объяснение включено в основной ответ, оценщик получает этот текст с пометкой источника. Регрессионные тесты покрывают обе стороны контракта.

В локальном окружении дважды аварийно завершался `gnome-keyring-daemon` при обработке Secret Service: журнал указывает на ошибки `gkd_secret_service_get_pkcs11_session`/`GVariant`, но не показывает, какое приложение отправило запрос. Сервис автоматически перезапускался; нехватки памяти не было. educatioHarness теперь кэширует только признак наличия API-ключа на 60 секунд вместо чтения хранилища каждые шесть секунд. Сам ключ не кэшируется и по-прежнему запрашивается из системного хранилища только для API-вызова. Проверка входа с действительным API-ключом пока не выполнена.

Codex SDK получает отдельный пустой рабочий каталог, `sandboxMode: read-only`, `approvalPolicy: never`, `networkAccessEnabled: false` и выключенный web search. Из окружения Codex-процесса удаляется случайно унаследованный `OPENAI_API_KEY`. Это защита от записи и сетевых инструментов, но не криптографическая изоляция чтения всех файлов пользователя: пока обучение использует Codex SDK, CLI может иметь read-only доступ к файлам, которые доступны процессу ОС. Вызовы OpenAI Responses API не получают локальные инструменты.

Экспорт и импорт основаны на SQLite Online Backup API (`rusqlite::backup`), а не на копировании активного WAL-файла. Защищённый перенос использует `.ehb`: заголовок `EDUHBA01`, случайные соль (16 байт) и nonce (12 байт), затем аутентифицированный шифртекст ChaCha20-Poly1305. Ключ: Argon2id, 64 МиБ, 3 прохода, 1 поток. Лимит исходной базы — 100 МБ; формат версии 1 не содержит изменяемых параметров KDF. Пароль не сохраняется. На время импорта расшифрованная база лежит в локальном каталоге данных с правами 0600 на Unix, затем удаляется; до импорта неверный пароль или повреждение отклоняются. Предпросмотр проверяет `integrity_check`, внешние ключи и версию схемы. Архив сначала копируется во временную приватную базу: там выполняются миграции и удаляются чужие настройки сервера/навыков. Только после успешной проверки подготовленной базы создаётся `before-import-<uuid>.sqlite3` и заменяется открытая база; при ошибке замены приложение пытается автоматически восстановить её из резервной копии и сообщает путь к копии. Временная база удаляется после операции. Архив не содержит API-ключей, но включает личные ответы и тексты занятий. Файловые диалоги доступны только основному окну через ограниченные Tauri capabilities.

`sync-server/` собирается командой `npm run sync-server:build`, проверяется `npm run sync-server:test` (также входит в `npm test`) и запускается `npm run sync-server:start` с `EDUCATIO_SYNC_DATA_DIR` и `EDUCATIO_SYNC_TOKEN`. По умолчанию это однопользовательский сервер шифртекстов; с `EDUCATIO_AGENT_API_KEY` он также запускает учебный OpenAI runtime, а с `EDUCATIO_AGENT_PROVIDER=codex` и отдельным рабочим каталогом — Codex SDK с официальным входом CLI на сервере. Протокол запроса не даёт клиенту сменить серверный режим. Codex-процесс получает только нужные переменные окружения, включая явно перечисленные настройки прокси/CA, но не API-ключ; на проверенной сессии реальный запрос через авторизованный HTTP endpoint завершился `200`. Desktop-команды архива работают в blocking-пуле Tauri, AI-вызовы через сервер — асинхронно. Клиент запрещает редиректы, системные прокси, сжатие ответов и HTTP для адресов вне loopback, проверяет размер скачивания и сравнивает ETag с последней известной версией до отправки. На компьютере токен хранится в системном keyring, на мобильной ветке временно только в памяти; при импорте базы настройки текущего сервера и его ETag остаются локальными. Подробнее: [sync-server.md](sync-server.md).

Настройка каталога данных копирует активную базу тем же Backup API в `educatioHarness/educatio-harness.sqlite3` внутри выбранной папки, пишет `data-directory.json` в стандартный каталог приложения и перезапускает процесс. Старый файл остаётся резервной копией. Существующая база в месте назначения не перезаписывается. Если указанный каталог после переноса недоступен, приложение выдаёт ошибку при открытии базы вместо тихого создания новой пустой базы; для восстановления можно вернуть каталог или исправить конфигурационный файл вручную.

Адаптивный интерфейс проверен в нативном Tauri-окне размером 390×780: нижние разделы, экран обучения, выдвижной план с редактированием темы, практика, граф и настройки. Для этого минимальная ширина desktop-окна снижена до 340 px. Такая проверка подтверждает компоновку WebView, но не установку на Android/iOS. Android Rust target установлен; Android SDK/NDK пока отсутствует, поэтому APK не собран и мобильная ветка не проверена на устройстве. Tauri-конфигурации для Android/iOS исключают desktop Node/Codex sidecar; мобильный AI-маршрут идёт через свой сервер.
