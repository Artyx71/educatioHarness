# Архитектура

educatioHarness разделён на три процесса: Tauri отвечает за окно, команды, SQLite и системное хранилище секретов; React отображает состояние; Node.js runtime выполняет запросы Codex SDK или OpenAI Responses API. Сохранённый API-ключ никогда не возвращается во фронтенд; при первоначальном вводе поле React передаёт его одной Tauri-командой для проверки и безопасного сохранения. Запрос модели передаётся дочернему процессу через stdin, прогресс и результат — ограниченными JSONL-событиями через stdout. Tauri пересылает только число полученных символов в UI: непроверенный JSON и скрытое решение задания не показываются. Нет локального HTTP-сервера для агента.

`src/lib/workflow.ts` содержит общий контракт перехода шага: ID, статус, вход/выход, зависимости, ошибку, число повторов, метаданные и привязку к занятию. Начало шага разрешено только после завершения его зависимостей; шаг урока отдельный для каждого занятия. `src/features/learning/engine.ts` задаёт специализацию обучения: диагностика, оценка, план, урок, практика и извлечение графа. Итоговое повторение — отдельный сохранённый workflow: после каждого созданного вопроса он записывает ID упражнения и может продолжить с первого отсутствующего. `agent-runtime/src/main.ts` содержит небольшой провайдерный интерфейс и схему структурированных результатов. Перед сохранением плана движок дополнительно проверяет уникальность ID тем, существование предпосылок и отсутствие циклов, затем упорядочивает темы по зависимостям. Невалидный ответ помечает шаг как ошибочный и не заменяет прежние данные. Другой workflow сможет использовать тот же транспорт и хранилище, добавив собственные операции и навыки.

SQLite открывается только в Rust (`src-tauri/src/lib.rs`). Миграции находятся в `migrations/`, версия хранится в `PRAGMA user_version`. Транскрипты, диагностические ответы, темы, попытки, граф и состояния шагов — отдельные таблицы с внешними ключами. Команды записи ограничены перечнем таблиц и полей. Значимые переходы workflow сохраняются до и после вызова модели. После перезапуска незавершённую диагностику можно повторить явно; операции не перезапускаются автоматически. Уже записанные ответы подставляются обратно в форму; завершённая оценка повторно используется, если ответы не изменились. Незавершённый учебный план скрыт до успешного окончания шага и заменяется целиком при повторе. Выбранное пользователем расположение базы хранится в небольшом файле конфигурации в стандартном каталоге приложения. Смена каталога создаёт согласованную копию через SQLite backup и перезапускает Tauri; исходный файл не удаляется.

Родной процесс Codex использует официальный вход `codex login`. SDK создаёт и возобновляет thread; его ID хранится отдельно для каждой операции и учебной сессии. Для нового занятия той же цели учитель получает короткую историю предыдущих занятий и утверждения графа, явно помеченные как записи, а не доказательство понимания. Практика учитывает прежние попытки только по выбранной теме. Codex SDK `runStreamed` и OpenAI Responses `stream: true` дают события выполнения. OpenAI SDK вызывается только с API-ключом из системного хранилища. Ключ передаётся дочернему процессу через переменную окружения, не через renderer или SQLite. Каждый вызов имеет таймаут 180 секунд и может быть отменён. В production Node поставляется отдельным исполняемым sidecar, а runtime — собранным модулем.

Граф хранит объективные утверждения и цепочки совместных посылок. Источники фиксируются в `knowledge_provenance`; связи с темами — отдельно в `knowledge_topic_links`, потому что одно утверждение может относиться к нескольким темам. Панель узла показывает исходное сообщение и открывает связанное занятие. Узел не означает, что ученик усвоил утверждение. Фильтр по теме использует только явные связи; старые утверждения без такой связи остаются видны в режиме «Все темы». Автоматический layout React Flow строится по цепочкам, а повреждённые JSON-записи связей игнорируются вместо падения интерфейса.
