# Что развивать дальше

Сейчас доступны диагностический маршрут, интерактивный учитель, практика с карточками, редактор кода, математический предпросмотр, граф знаний, карта активности, перенос базы между компьютерами и односторонний экспорт заметок в Obsidian. Ниже — отобранные улучшения, а не список уже готовых функций.

1. **Повторение по следам ошибок.** Показывать темы, которые давно не вспоминали или по которым были частично/неверно оценённые ответы. Новый вопрос должен менять контекст и не раскрывать название метода. Интервалы — предложение для повторения, не «процент освоения». Основание: обзоры [retrieval practice с обратной связью](https://pubmed.ncbi.nlm.nih.gov/29929801/) и [распределённой практики](https://pubmed.ncbi.nlm.nih.gov/37615780/). Уже есть первый слой — карточки и даты ответов; планировщика пока нет.
2. **Отладчик предпосылок.** После ошибки находить ближайший шаг рассуждения, на котором ответ разошёлся с проверяемым решением, и предлагать маленькую задачу на эту предпосылку. Сохранять наблюдение с источником, не объявлять человека «не знающим тему». Это опирается на существующий граф LearnHarness и его различие между фактами и свидетельствами ответа.
3. **Итоговое повторение с переносом.** Несколько задач из разных тем без явных подсказок, затем разбор цепочек рассуждения. Для математики полезно смешивать типы задач: [исследование interleaving](https://pubmed.ncbi.nlm.nih.gov/30877483/) показывает эффект в изученной постановке; не стоит превращать его в универсальный лозунг. Потребуется отдельный режим и сохранённый протокол итоговой попытки.
4. **Проверяемая практика по коду.** Запускать тесты только в изолированном окружении с лимитами времени/памяти, без сети и доступа к личным файлам. До появления такой песочницы редактор лишь помогает писать код, а проверка ИИ не выдаётся за выполненные тесты.
5. **Obsidian.** Экспорт Markdown в отдельную папку выбранного хранилища уже есть. Следующий шаг — ссылки на конкретные сообщения и выбор заметок для импорта. Двусторонний обмен требует правил конфликта и доверия к стороннему Markdown; [официальный Vault API](https://docs.obsidian.md/Plugins/Vault) пригоден для отдельного плагина, но не нужен простому экспорту.
6. **Аккаунт и синхронизация.** Локальные занятия должны оставаться доступными без регистрации. Для сервера нужен отдельный согласованный протокол: шифрование, версии записей, конфликты при офлайн-редактировании, отзыв устройств и понятное удаление данных. Экспорт/импорт — первый переносимый формат, не замена синхронизации.
7. **Телефоны.** [Tauri 2 поддерживает Android/iOS](https://v2.tauri.app/develop/), но [мобильные sidecar сейчас остаются проблемой Tauri](https://github.com/tauri-apps/tauri/issues/9774). Потребуется Rust/нативный или удалённый провайдерский транспорт, мобильный файловый импорт и компактная навигация. Нельзя просто упаковать текущий Node/Codex CLI.

Внешние учебные навыки не копируем по «звёздам»: опубликованные подборки редко имеют проверяемый рейтинг эффективности. Подходящие методы изучаем по инструкциям, лицензии и педагогическим данным. Новый `retrieval-review` оставляет фиксированную схему результата и ограничение разрешений приложения.
